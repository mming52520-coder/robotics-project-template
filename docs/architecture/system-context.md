# System Context

For the repository's indoor wheeled-robot reference, see `docs/reference/indoor-wheeled-robot.md` and ADR-0001. A derived project must replace the sections below with its own verified facts.

## Purpose

Describe the problem, users, operating environment, and boundaries.

## Components

List software nodes, firmware, hardware functions, sensors, actuators, transports, and external services. Keep hardware descriptions model-free in public artifacts.

## Interfaces

Document message schemas, units, frames, timing assumptions, ownership, and failure behavior.

## Safety boundaries

Identify control authority, interlocks, watchdogs, stop behavior, reset behavior, and simulation boundaries. State that hardware output is disabled until a documented human-approved procedure exists.

## Open questions

Record unknowns that could change architecture or acceptance criteria.
